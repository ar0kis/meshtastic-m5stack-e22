# ESP32-C3 E22-900M22S Repeater Observer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce and validate a standalone Repeater+MQTT Observer firmware for ESP32-C3 Super Mini + E22-900M22S while preserving the existing node identity.

**Architecture:** Add a dedicated board variant based on the existing Xiao C3 target implementation and the existing EoRa-S3 observer environment. Keep hardware pin selection and observer composition declarative in the variant `platformio.ini`; reuse the fork's MQTT bridge, NTP, runtime Wi-Fi/MQTT configuration, and simple repeater implementation.

**Tech Stack:** PlatformIO, Arduino ESP32, MeshCore Flex Observer, RadioLib SX1262, PsychicMqttClient, ArduinoJson, NTPClient.

**Spec:** `docs/superpowers/specs/2026-11-13-esp32-c3-e22-m22s-observer-design.md`

## Global Constraints

- Do not use settings from `meshcoretel.ru`.
- Keep `869.050 MHz / 62.5 kHz / SF8 / CR7 / 22 dBm`.
- Keep the existing private key and full Repeater ID.
- Never print, commit, or publish the private key, Wi-Fi password, or MQTT credentials.
- Target 4 MB flash and no PSRAM or display.

## Review Focus

- GPIO contract must distinguish E22-900M22S from E22-900MM22S.
- RXEN and TXEN must remain separate MCU-controlled active-high pins.
- The merged image must fit 4 MB and include the observer certificate bundle.
- Runtime configuration must not contain baked-in MeshCoreTel or other credentials.
- A full erase must not permanently change the node identity.
